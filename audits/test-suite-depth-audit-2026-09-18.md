# Test-suite depth audit — 2026-09-18

Read-only audit of how much the existing NixOS tests, flake checks, and eval-time invariants actually _prove_, fleet-wide. Builds on `main-audit-2026-09-17.md` §6 (missing tests for `hosts/main`) and does not re-list those gaps; this report is about the strength of what already exists. No repository files were changed.

What ran: `bash scripts/validate.sh flake-eval` (exit 0); `nix build` of every eval-only "fixture" check plus the two checks no CI lane builds; a `nix eval` probe that re-assembles each fixture's module list and forces `assertions` / `system.build.toplevel`; `nix derivation show` on `deploy-activate`; inspection of the pinned nixpkgs (`misc/version.nix`, fail2ban module + `action.d/nftables.conf`).

Confidence labels: **verified** (eval, build, or upstream source read), **plausible** (strong inference, not directly observed), **speculative**.

Inventory audited: 4 VM tests (`tests/nixos/`), 34 `checks.*` attributes (`flake/checks.nix` + `flake/dev.nix` + `tests/lib`, `tests/home`, `tests/packages`), 29 invariant definitions in `lib/invariants.nix`, `scripts/validate.sh`, `scripts/ci-plan.sh`, `.github/workflows/nix.yml` / `deploy-homeserver.yml`.

## 1. False-confidence tests (would stay green with the feature broken)

1. **`flake/checks.nix:592-646` (`mini-fleet-example-fixture`) + `examples/mini-fleet/hosts/server-example/default.nix`** — The fixture forces `system.build.toplevel` only for the _workstation_ (`:618-620`, `:643-644`); the server is sampled for three attributes (`:637-640`) and never toplevel-forced. Probe: the server assembly (same module list as `:621-630`) has a failing NixOS assertion, `You must set the option 'boot.loader.grub.devices' …`, and `toplevel.drvPath` does not evaluate. The workstation got its placeholder `boot.loader.grub.devices` on 2026-06-14 (`workstation-example/default.nix:17-21`); the server never did. So the copyable server example is unbuildable today, and the check whose README purpose is "prove it doesn't rot … fails CI before it could ever reach a real host" (`examples/mini-fleet/README.md:53-58`) is green. The archived learning candidate `2026-06-09-fixtures-must-force-toplevel-to-check-assertions` identified exactly this class and the fix was applied to one of the two hosts. **Verified.** Next: add the `by-label` grub placeholder to `server-example`, `deepSeq` its `toplevel.drvPath` like the workstation, and assert the sampled values (`serverMetricsURL == "https://observability.example.ts.net/ingest/metrics"`, `CapabilityBoundingSet == ""`) instead of writing them to JSON.

2. **`flake/checks.nix:386-425, 427-464, 520-560, 566-585` (`observability-stack-fixture`, `observability-client-fixture`, `services-hardened-example-fixture`, `profiles-base-standalone-fixture`)** — Each evaluates a module set, samples a handful of option values, and `writeText`s them as JSON. Nothing compares the values to an expectation: `{"grafana":true,"loki":true,…}`, `{"metricsURL":"https://observability.example.ts.net/ingest/metrics",…}`, `{"configurationRevision":null,"hasExportSystemMetadata":false,…}` are the literal outputs. If `services.loki.enable` evaluated to `false`, or the client built `https://host//ingest/metrics`, the check would record it and pass. They also never touch `toplevel`, so NixOS assertions are skipped: the probe shows the stack fixture's own config trips nixpkgs' Grafana assertion _"secret key … doesn't have a default value anymore"_ (the fixture sets `adminPasswordFile` but not `secretKeyFile`, `:400-403`), plus the usual root-fs/bootloader assertions on all four. These are "module evaluates without throwing" smoke checks presented as fixtures. **Verified (built all four; probe eval).** Next: turn each `evaluated` set into `assert evaluated == expected` (or `lib.runTests`), give each fixture a `by-label` root fs + grub placeholder and `deepSeq` `toplevel.drvPath` (the pattern `observability-dashboard-backend-assertion-fixture` at `:466-515` already uses correctly), and add `secretKeyFile` to the stack fixture so it matches `docs/observability-stack.md:62`.

3. **`tests/nixos/profile-security.nix:92-101`** — The comment says "Verify the nftables ban rule was actually installed (not just internal counter)", but the assertion is `nft list ruleset | grep -qE '2001:db8:1::1|f2b'`. fail2ban's nftables action creates `table inet f2b-table` at _jail start_ (`action.d/nftables.conf:87 actionstart = <nftables> add table …`; `actionban` at `:120` only adds a set element), so `f2b` matches before any ban exists; the `2001:db8:1::1` alternative never matches a NixOS test network (192.168.1.0/24). The follow-up `attacker.fail(… -p wrongpassword …)` at `:96-101` cannot distinguish "firewalled" from "wrong password". Net effect: the only real assertion is fail2ban's `Currently banned` counter, so a broken `banaction` (nft not on PATH, table family mismatch) would pass. **Table-at-start verified against the pinned fail2ban; "counter increments despite failed action" plausible.** Next: assert the attacker's address is in the set (`nft list set inet f2b-table addr-set-sshd | grep -q 192.168.1.<n>`) and make the final probe use the _correct_ password with `ConnectTimeout`, expecting a timeout rather than an auth failure.

4. **`tests/nixos/homeserver-gcp-smoke.nix:165-167`** — `if not os.path.exists('/dev/kvm'): … sys.exit(0)` inside the test script makes the derivation succeed without booting anything. The CI `tests` job force-declares `system-features = … kvm` (`.github/workflows/nix.yml:338-339`, also `deploy-homeserver.yml:85-86`), so a runner _without_ `/dev/kvm` still schedules the derivation, at which point the skip fires and the smoke test is green with zero assertions executed. `scripts/validate.sh:314-317` repeats the same exit-0 skip on the host side, while `profile-tests` / `heavy` (`:327-342`) have no such guard, so the guard's presence is inconsistent as well. Whether a CI run has ever taken the skip path is not knowable offline. **Skip path verified by reading; CI scenario plausible.** Next: replace `sys.exit(0)` with a hard failure (or drop the guard and rely on the `kvm` system feature), and make `validate.sh smoke-homeserver-gcp` exit non-zero with a clear message when KVM is absent.

5. **`lib/invariants.nix:445-448` (`hasStateVersion`, in `commonSystemInvariants` for every host)** — `cfg.system.stateVersion != null` can never be false: the option is `types.str` with an `apply`-time default plus warning (pinned nixpkgs `nixos/modules/misc/version.nix:216-224`). It is a tautology that reads as a fleet baseline. **Verified.** Next: assert `options.system.stateVersion.highestPrio < (lib.mkOptionDefault {}).priority` (i.e. explicitly set) or drop it.

6. **`flake/checks.nix:314-342` (`alerting stack has direct failed-unit webhook fallback`, homeserver-gcp)** — Asserts `enable`, the exact `webhookUrlFile` path, and the exact unit list. All three are option _wiring_; none exercises `notify-failure@.service`. The prior audit found the notifier script dies on `systemd-cat` → `/bin/cat` before posting anything (`modules/nixos/services/systemd-failure-notify.nix:22`), and this invariant stayed green throughout. It is the concrete fleet-wide instance of "the option is set" masquerading as "the mechanism works". **Verified.** Next: keep the wiring check but pair it with the VM test the prior audit proposes (§6.1), which is the only thing that would have caught the bug.

7. **`flake/checks.nix:648-662` (`mkSopsBootstrapCheck`, `<host>-sops-bootstrap` for mac / homeserver-gcp / gcp-agent)** — Only `builtins.pathExists` on the two `.enc` files. A 0-byte or truncated `.enc` passes — precisely the failure mode the repo's own `CLAUDE.md` "Secrets" section records (a `sops -e … > out.enc` that exited 127 and left an empty file). The real files are sops JSON (`{"data": "ENC[AES256_GCM,…`, ~2 KB). **Verified.** Next: in the runCommand, require non-empty files and `grep -q '"sops"'` / `ENC[` (or `sops filestatus`), which needs no key material.

8. **`tests/nixos/homeserver-gcp-smoke.nix:219-224`** — "Authenticated ingest reaches a backend" is `grep -qEv '^(401|404|502)$'` on `%{http_code}`. curl reports `000` on connection failure, which the negative grep accepts. Low today because earlier steps already waited for nginx, but the pattern is a silent pass. **Verified by reading.** Next: assert a positive set (`^(200|204|400|405|415)$`).

## 2. Checks that never run, or run somewhere weaker than advertised

1. **`flake/checks.nix:717-732` (`invariants-registry-security`) vs `scripts/validate.sh:264-291`** — This is the only place `checkSopsRecipientParity` (`.sops.yaml` rules/keys ⇔ active registry hosts) and `checkDeployTargetsHaveTailnetAddresses` are enforced. `mkInvariantCheck` (`lib/invariants.nix:892-908`) reports failure by building an `exit 1` derivation, so the check only fails when _built_ — and no validate target, no workflow, and no doc references it (repo-wide grep: zero hits outside its definition). `light` hand-lists 20 of the 34 checks and omits it. A `.sops.yaml` edit that drops a host recipient is a `run_eval + run_light` change under `scripts/ci-plan.sh` and would sail through merge-gate. Built locally today: passes. **Verified.** Next: add it to `light`, or better, stop hand-listing and build `nix flake check` minus an explicit exclude set.

2. **`flake/dev.nix:260-262` (`control-center-capabilities`)** — Same failure mode (Python asserts inside a `runCommand`), same omission from `light`; `packages/` changes trigger `package all`, which builds the app but not this test. Never built in CI. Built locally: passes. **Verified.** Next: add to `light`.

3. **`scripts/validate.sh:260-262` (`flake-eval` = `nix flake check --no-build`)** — Cannot detect a failing invariant. Probe: `mkInvariantCheck "probe" [ { check = _: false; } ] {}` evaluates cleanly to `invariant-check-probe-fail` under `--no-build`. So the "fast evaluation gate" that `CLAUDE.md`, `doctor.sh:71-76`, and yesterday's audit treat as a health signal proves only that invariants _evaluate_, not that they _pass_; only `light` (build) does. The 14 checks absent from `light` split into 12 that fail at eval time (`lib.runTests`/`throw`/`assert` — genuinely caught by `flake-eval`) and the 2 above that do not. **Verified.** Next: document the distinction in `CLAUDE.md`'s validation table, and consider making `mkInvariantCheck` `throw` at eval time (or `builtins.abort`) so `flake-eval` and IDE evaluation both surface failures.

4. **`flake.nix:219-224` + `scripts/ci-plan.sh:15`** — VM tests live under `legacyPackages.ciTests`, which `nix flake check` intentionally ignores, so `flake-eval` never even parses `tests/nixos/*.nix`. Their evaluation happens only in the path-gated `tests` job (`tests/nixos/`, `hosts/homeserver-gcp/`, all-hosts modules, flake/lib). The gating rules are sound; the gap is that a local `flake-eval` cannot tell you a VM test file is syntactically broken. **Verified.** Next: add `nix eval .#legacyPackages.x86_64-linux.ciTests --apply builtins.attrNames` (forces the test derivations) to `flake-eval`.

5. **`scripts/validate.sh:264-291` (`light`) builds four full host closures** — `deploy-activate` (from deploy-rs `deployChecks`) has `activatable-nixos-system-{gcp-agent,gcp-builder,homeserver-gcp,mac}` as inputs (`nix derivation show`). So the "lightweight blocking checks" lane is where mac/gcp-builder/gcp-agent/homeserver-gcp closures are actually built on every non-docs PR; the `hosts` CI matrix (`ci-plan.sh:190-200`) only ever contains `main-ci` and `installer`. Coverage is fine; the naming hides the cost and the coupling that `hosts/homeserver-gcp/CLAUDE.md` "Gotchas" describes (an unrelated mac package break fails the homeserver deploy's `light`). **Verified.** Next: rename or document; if `deploy-activate` is the intended closure gate, drop the duplicate `host` targets from the deploy workflow or vice versa.

6. **`lib/invariants.nix:398-418` (`checkExpectedTrustedUsers`)** — Unit-tested three ways (`tests/lib/invariants.nix:555-581`) but used by no check; the live enforcement is an independent copy of the same logic in `modules/nixos/profiles/nix-trusted-users.nix:3-14`, which has no test. A dead function with tests and a live assertion without them. **Verified (grep).** Next: have the module call the lib function, or delete the lib function and its tests.

7. **`tests/lib/invariants.nix:429-432` (`tailnetTagsHaveAdguardDnsGrantPassesOnRealRegistry`)** — A fleet invariant (every active tag has a `:53` grant on homeserver-gcp) is enforced only because a _unit-test file_ happens to run it against `lib/hosts.nix`; `checkTailnetTagsHaveAdguardDnsGrant` (`lib/invariants.nix:140-163`) is not in `registrySecurityInvariants` or any host list. It works (eval-time, in `light` via `lib-invariants`), but it is easy to lose in a test refactor. **Verified.** Next: move it next to `checkSopsRecipientParity` in `registrySecurityInvariants` once §2.1 makes that check run.

## 3. Weak, wiring-level, or self-referential assertions

1. **`lib/invariants.nix:494-509` (`mainSshIsTailnetOnly`)** — Checks `openssh.enable`, `openFirewall = false`, `tailscale.enable`, `tailscale.openFirewall`. It does not check that port 22 is absent from `networking.firewall.allowedTCPPorts` or from non-`tailscale0` interfaces, which is exactly what the mac and homeserver variants do via `checkTCPPortsRestrictedToInterface` (`:762-788`). Today `main` has `allowedTCPPorts = []` and `tailscale0 = [22 24800 47984 47989 48010]` (eval), so the state is right, but adding `allowedTCPPorts = [ 22 ]` to `hosts/main` would keep "main SSH stays tailnet-only" green. **Verified.** Next: append `interfaceTCPExposureViolations { interface = "tailscale0"; ports = [ 22 ]; }` like `gcpBuilderSshTailscaleOnly` (`:790-806`).

2. **`flake/checks.nix:205-222` (`rollbackRootInitrdToolsAvailable`) and `:16-38` (`nixpkgsRegistryPinnedToFlakeInput`)** — Both assert values that the repo's own shared code sets unconditionally (`impermanence-base.nix:72-76` adds exactly those three packages when `rollbackRoot.enable`; `flake/hosts.nix:94-97` sets the registry/nixPath for every host). They only catch a host `mkForce`-ing the value away — legitimate, but they are checking the setter's own output, not an independent property. Same shape as `homeserverGcpB2BackupUsesCriticalPolicy:230-232`, which compares `pruneOpts` against the very file the module reads (the comment admits it). **Verified.** Next: keep, but relabel in comments as "override guards" so nobody mistakes them for substance checks; for rollback-root, the substantive check would be a VM test of the initrd script.

3. **`lib/invariants.nix:371-396` (`tailscale0FirewallPortsMatchAcceptFrom`)** — Unions `allowedTCPPorts ++ allowedUDPPorts` before comparing with `acceptFrom`. A port the ACL admits (Tailscale `tag:x:port` covers both protocols) but the firewall opens on only one protocol passes. `main`'s Sunshine UDP ports (`lib/hosts.nix:56-63`) are the live case where this matters. **Verified.** Next: compare per protocol, or have the registry declare the protocol.

4. **`tests/nixos/homeserver-gcp-smoke.nix:198-205`** — "Vaultwarden notification websocket route is explicit and reaches the upstream" greps `location = /notifications/hub` out of the generated `nginx.conf`; nothing is sent to it. More importantly, the smoke test never asserts a single security header, although `hosts/homeserver-gcp/nginx.nix:11-21` exists precisely because nginx `add_header` inheritance silently drops them per-location and every location re-injects `securityHeaders`; a new location without the re-injection would ship unnoticed. The `adguard-ui` vhost (`nginx.nix:70-87`) and the `/home/` status-page routes (`:149-208`) are also unexercised. **Verified.** Next: `curl -skI` `/`, `/grafana/`, `/home/`, `/home/status.json` and assert `Strict-Transport-Security` + `Content-Security-Policy` on each; add a websocket handshake (`-H 'Upgrade: websocket'`) expecting `101`/`400` from Vaultwarden rather than nginx `404`.

5. **`tests/home/theme-module.nix:27-34, 104-107, 129-132`** — The module is called as a plain function with a stub `config` and its returned attrset is inspected directly; it never goes through `evalModules`, so option types/defaults are unchecked and the test silently constrains `home/theme/module.nix:276` to keep a bare `config = { … }` (a top-level `mkIf`/`mkMerge` would break `files ? "themes/mono-mesh/vars"` rather than be evaluated). `testSwitcherShipped` / `testDocExampleActivatesSwitcher` assert `length home.packages >= 1`, satisfied by any package. **Structure verified; type-check blind spot plausible.** Next: evaluate through `home-manager.lib.homeManagerConfiguration` (or `lib.evalModules` with HM's option stubs) and assert the switcher package by `pname`.

6. **`tests/lib/mini-fleet-flake.nix:41-55`** — Checks that each public output name appears in the example flake and that the _bare attr name_ (`profiles-desktop`, `observability-client`, …) appears _anywhere_ in the root `flake.nix`, comments included. A rename that leaves a comment behind passes. **Verified.** Next: `nix eval .#nixosModules --apply builtins.attrNames` and compare.

7. **`tests/nixos/profile-observability.nix:188-192` (Test 4)** — Proves remote-write reached Mimir by `grep -q '"job"'` on `query=up`; it does not pin the scraped job or `up == 1`. Adequate as a liveness check, weak as a contract. **Verified.** Next: query `up{job="node"} == 1` (or whatever the module's job label is) via `/prometheus/api/v1/query` and parse JSON.

8. **`tests/lib/doctor.nix:68-101`** — A golden test on the _text_ of `scripts/doctor.sh` (section banners in order, a keyword within 6 lines). It never runs doctor, so a section whose command is wrong (e.g. `run bash scripts/validate.sh light` under `--with-builds` at `doctor.sh:85-99`, which the public README presents as the clean-clone entry) stays green. Acceptable for its stated purpose; note it is a contract-shape test, not a behaviour test. **Verified.** Next: none required; optionally run `doctor.sh` with `nix` stubbed to assert it reaches each section.

## 4. Redundant coverage next to untested duplicates

1. **`services.hardened` is tested four ways** — `tests/lib/services-hardened.nix` (eval, 9 assertions, strong), `tests/nixos/profile-hardening.nix` (VM, `systemd-analyze security` score + effective properties, strong), `services-hardened-example-fixture` (no assertions, §1.2), and the mini-fleet server's `demo-app` (sampled, not asserted, §1.1). None of the four covers `services.hardened.<name>.enable = false` (`modules/nixos/services/hardened.nix:134`), the one branch where the DSL must _not_ touch a unit. **Verified.** Next: delete or assert-ify the two fixture samples; add an `enable = false` case to the eval unit test.

2. **Grafana auth-proxy config is duplicated into the smoke test** — `tests/nixos/homeserver-gcp-smoke.nix:79-92` hand-copies `hosts/homeserver-gcp/grafana.nix:74-82` (already drifted: `sync_ttl = 0` vs `60`) instead of importing it, and stubs the identity helper with a Python server that always answers 204. The real helper `hosts/homeserver-gcp/grafana-tailscale-auth/main.go` (`tailscale whois` → role map) has no test of any kind (grep across `tests/`, `flake/`). So the test proves nginx's `auth_request` plumbing with the test's own Grafana settings; a header-name typo in `grafana.nix` or a role-mapping bug in the Go helper is invisible. **Verified.** Next: import `../../hosts/homeserver-gcp/grafana.nix` with the helper's `tailscale` dependency mocked, or at minimum assert the smoke identity lands (`/grafana/api/user` → `viewer@example.com`) and add a `go test` for the role map.

3. **Dashboards have a negative eval test but no positive runtime test** — `observability-dashboard-backend-assertion-fixture` (`flake/checks.nix:466-515`) proves a dashboard bound to a disabled backend fails eval (correct pattern, forces `toplevel`). Nothing proves Grafana _accepts_ the 300+ lines of provisioned JSON from `modules/nixos/profiles/observability/dashboards.nix`; the smoke test waits for `grafana.service` and fetches `/grafana/` (200), and Grafana logs provisioning errors without failing the unit. **Plausible.** Next: in the smoke test, `GET /grafana/api/search?type=dash-db` through the auth proxy and assert the expected UIDs.

## 5. Boundary-test leakage and standalone claims

1. **Module sources are clean** — `modules/nixos/profiles/{observability,observability-client.nix,base.nix,desktop.nix,security.nix}`, `modules/nixos/services/*`, `home/profiles/{base,desktop}.nix`, `home/theme/module.nix` contain no `hostMeta`, `hostRegistry`, `inputs`, `self`, or `fleet.*` references (grep); the fixtures use `lib.nixosSystem` with no `specialArgs`. The private-fleet coupling is real only where `docs/public-adoption.md:264-281` already says it is (backup/sops-base/user/impermanence). **Verified.**

2. **But the standalone _proof_ is thinner than the docs say** — `examples/mini-fleet/README.md:53-58` ("evaluates both hosts … fails CI before it could ever reach a real host") is false for the server (§1.1); `docs/public-adoption.md:34-36` cites `mini-fleet-example-fixture` as the Track-3 guarantee; `flake.nix:229-234` says the lib boundary tests "prove they build outside the personal host assembly" — true for `lib-dashboards`/`lib-generators`/`lib-acl` (real zero-context imports with negative cases), not for the four `writeText` fixtures (§1.2). **Verified.** Next: fix §1.1/§1.2, then the docs are accurate without edits.

3. **`tests/home/theme-module.nix:97-100` (`testActiveFileDefault`)** — Pins the module default `activeFile = "$HOME/nix/home/theme/active.nix"`, i.e. the private assumption that the repo is checked out at `~/nix`. The test enshrines the leak instead of flagging it; an adopter with the repo elsewhere gets a dangling default unless they read `docs/theme.md`. **Verified.** Next: default to the theme module's own `themeDir + "/active.nix"` (store path) and test that; keep the override example.

4. **`profiles-base-standalone-fixture` records `hasExportSystemMetadata = false`** (`flake/checks.nix:581`) — The comment says the public `profiles-base` "must not depend on observability internals"; the fixture would record `true` just as happily if it did. Folded into §1.2's fix.
